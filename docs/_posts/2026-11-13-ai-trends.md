## 📌 오늘의 한 줄 요약
계획은 큰 모델이, 실행은 빠른 모델이 맡고, 공유 자원에는 코디네이터 하나를 두라는 흐름이 뚜렷합니다. 학습 결과를 git에 커밋해 쌓는 '자기 개선 에이전트' 패턴도 나왔습니다.

## 🎯 활용 Best Practice

### 계획은 Carbon, 실행은 Hydrogen: 모델을 세션 안에서 나눠 쓰기 (Google, 11/12)
- Antigravity의 새 Orchestrator는 Gemini 4 Carbon이 읽기 전용 모드로 의존성을 살피고 "다시 계획할 조건"까지 담은 계획을 세웁니다. 편집과 테스트 실행은 Hydrogen이 맡습니다. Hydrogen이 막히면 Carbon이 상태를 점검해 계획을 고친 뒤 이어 갑니다.
- Google은 Terminal-Bench 4.1에서 Carbon 단독에 가까운 성공률을 내면서 쿼터를 약 24% 덜 쓰고 평균 19% 빨랐다고 밝혔습니다. 일상 작업마다 프런티어 모델을 돌리면 "루프가 느려지고 쿼터만 태운다"는 설명입니다.
- **적용 팁:** 다른 도구를 쓰더라도 패턴은 같습니다. ① 큰 모델에는 읽기 전용 탐색과 계획만 맡기고 ② 계획에 "이런 일이 생기면 되돌아오라"는 조건을 적고 ③ 실행·테스트는 저가 모델에 넘기세요.
- 🔗 [Google Antigravity 블로그](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/)

### 여러 사용자의 에이전트가 자원을 나눠 쓸 때: 코디네이터를 하나 둬라 (Anthropic, 11/11)
- 토큰 예산, 진료 예약표, 단체 주문, 머지 큐 같은 공유 자원을 두고 "사용자별 에이전트 팀"과 "모든 사용자를 맡는 코디네이터 1개"를 비교했습니다. Claude 두 모델 모두 네 환경 전부에서 코디네이터가 약 10~45%p 앞섰습니다.
- 실패 원인은 타이밍이었습니다. 주문을 넣는 에이전트가 메시지를 다 읽기 전에 확정해 버렸고, 중요한 요청이 결제 시점 컨텍스트에 있었던 경우는 47~67%뿐이었습니다. 팀 구성에서는 다른 사람에 대한 근거 없는 주장도 53~58%의 에피소드에서 나왔습니다(단일 에이전트 17~20%).
- **적용 팁:** "읽지 않은 메시지가 있으면 확정(commit) 금지" 가드를 플랫폼에 넣으세요. 실패 에피소드의 62~73%가 이 가드만으로 회복됐습니다. 다른 사용자의 작업을 취소·축소할 때는 동의를 받게 하고, 팀이 꼭 필요하면 우선순위를 가진 리드 에이전트를 지정하세요.
- 🔗 [Anthropic Alignment Blog](https://alignment.anthropic.com/2026/worse-together/)

### 에이전트 학습은 "git 커밋 + 게이트"로 쌓아라 (AgentRun, Show HN)
- Claude Code·Codex 같은 하네스 위에 올리는 오픈소스 플랫폼입니다. 작업이 끝나면 에이전트가 남길 노트·스킬을 제안하고, 코드 검사 → LLM 채점 → (위험하면) 사람 승인을 통과한 것만 git `main`에 커밋됩니다.
- 같은 스킬이 3번 쓰이면 모델 호출 없이 도는 워크플로 초안을 만들고, 드라이런을 통과해야 채택합니다. 웹 페이지나 붙여넣은 메일에서 온 규칙, 비밀값이 섞인 답은 버립니다.
- **적용 팁:** 에이전트 메모리를 직접 쓰게 두지 말고 "제안 → 검사 → 커밋"으로 바꾸세요. 되돌리기가 쉬워지고, 외부 문서에서 주입된 규칙이 메모리에 눌러앉는 것을 막을 수 있습니다.
- 🔗 [AgentRun README](https://github.com/Parcha-ai/agentrun/blob/main/README.md) · [HN 토론](https://news.ycombinator.com/item?id=50471650)

### 결정적인 일은 도구에, 모델 전환은 같은 세션 안에서 (Apple Foundation Models)
- Apple의 Foundation Models 프레임워크가 같은 Swift API로 온디바이스 모델과 Claude·Gemini 같은 서버 모델을 함께 쓰게 했습니다. 'Dynamic Profiles'로 모델·추론 수준·도구를 세션 중에 바꿔도 대화 기록이 이어지며, 평가(Evaluations) 프레임워크와 `fm` CLI도 들어갔습니다.
- Apple 가이드의 핵심: OCR·바코드처럼 결정적인 작업은 모델 대신 Vision 도구로 하고, 지시문이나 모델을 바꿀 때마다 eval을 다시 돌리라는 것입니다.
- **적용 팁:** 서버 측 기능에는 일일 한도가 있으니 한도 초과 시 온디바이스 모델로 넘어가는 폴백을 처음부터 설계하세요.
- 🔗 [Apple Developer](https://developer.apple.com/foundation-models-framework/) (게시일 미표기, HN 11/12 화제)

## 🤖 새로운 모델
- **Gemini 4 Hydrogen (Google, 11/12):** Google이 "에이전트 작업의 데일리 드라이버"로 소개한 빠른 모델입니다. Artificial Analysis Intelligence Index 51(xhigh 54), Terminal-Bench 4.1 57%(3.8 Flash 18.2%)이며, 가격은 입력 $1.50/출력 $7.50(100만 토큰당, 1M 컨텍스트 전 구간 동일)입니다. 추론 수준은 low·medium·high(기본)·xhigh 4단계입니다. 🔗 [Google 블로그](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)
