## 📌 오늘의 한 줄 요약
에이전트 도구는 확장·벤더·로그까지 공급망으로 관리하고, 어시스턴트는 질문 그대로가 아니라 사용자가 실제로 원하는 것을 보도록 설계·평가하세요.

## 🎯 활용 Best Practice

### 코딩 에이전트 확장도 공급망이다: Cursor 사고 후속 (11/13)
- Cursor는 공유 스토리지 버킷에 쓰던 Fireworks용 접근 키가 유출된 것이 사고의 시작이었다고 밝혔습니다. 공격자는 그 데이터에서 찾은 자격 증명으로 마켓플레이스 캐시에 변조된 `Anthropic.claude-code` 2.1.312/2.1.313을 올렸습니다. 약 11시간 노출됐고 최대 5,000명이 받았을 수 있습니다. 유출 데이터는 주로 2025년 에이전트 기록이었고, 일부에는 가려지지 않은 자격 증명이 들어 있었습니다.
- Cursor는 "확장을 삭제하는 것만으로는 부족할 수 있다"고 경고했습니다. 2차 보도에 따르면 SSH 백도어를 심으려 한 빌드였습니다.
- **적용 팁:** ① 해당 버전을 설치한 적이 있으면 Cursor 10/29 공지 절차를 따르고 `~/.ssh/authorized_keys`를 점검하세요. ② 에이전트 세션이나 지원 문의에 붙여넣은 키는 유출됐다고 보고 교체하세요. ③ 팀에서는 에디터 확장 버전을 고정하고 허용 목록으로 관리하세요. ④ 벤더와 공유하는 버킷에도 비밀값 스캔을 돌리세요.
- 🔗 [Cursor](https://cursor.com/blog/security-incident-update) · [The Hacker News(2차)](https://thehackernews.com/2026/11/stolen-fireworks-ai-key-led-to-cursor.html)

### 모델은 질문 속 착각보다 질문 자체에 답한다: XYBench (AI2, 11/13)
- XYBench는 잘못된 접근(Y)을 묻지만 실제 목표는 X인 "XY 문제" 8,115개로 구성됐습니다. Stack Overflow 질문에서 5개 모델이 실제 목표에 초점을 맞춘 답은 35~41%뿐이었습니다. 반면 보기 중 고르게 하면 목표 중심 답을 71~84% 골랐습니다. 좋은 답을 알아보는 것과 직접 써내는 것은 다른 능력이라는 뜻입니다.
- 프롬프트에 목표를 알려 주자 목표 해결률은 59%에서 67%로 올랐지만, 착각을 짚어 주는 비율은 47%에서 34%로 떨어졌습니다(Sonnet 4.6).
- **적용 팁:** 지원·코딩 어시스턴트 시스템 프롬프트에 "답하기 전에 사용자가 이루려는 목표를 한 줄로 쓰고, 요청한 방법이 그 목표에 맞는지 먼저 판단하라"를 넣으세요. 평가는 "해결 여부"와 "착각 지적 여부"를 나눠 채점하세요.
- 🔗 [Hugging Face Blog (AI2)](https://huggingface.co/blog/allenai/xybench)

### 정렬 eval을 만들 때 "모호한 해킹"은 빼라 (LessWrong, 11/12)
- 6개월 동안 정렬 eval을 만든 Dean Valentine의 정리입니다. 최신 모델은 시험 중임을 알아채기보다 어디서든 "시험일지 모른다"고 가정하는 경향이 있다고 봤습니다. 과제를 더 현실적으로 만들거나 시험이라는 단서를 넣어도 보상 해킹 빈도는 크게 바뀌지 않았다고 합니다.
- **적용 팁:** 선의의 모델이 합리적으로 택할 수 있는 지름길이라면 "해킹"으로 집계하지 마세요. 과제에 적지 않은 규칙의 위반도 감점하지 마세요. 오래된 과제를 다듬기보다 새 과제를 늘리는 편이 효율적이라고 합니다.
- 🔗 [LessWrong](https://www.lesswrong.com/posts/mepsi7JNKYejq9wry/eval-awareness-vs-eval-paranoia)

### 사내 코딩 에이전트는 "게이트웨이 뒤"에 두라 (Databricks×OpenAI, 11/13)
- Databricks가 OpenAI 모델을 거버넌스가 적용된 데이터 위에서 쓰는 세 가지 패턴을 정리했습니다. ChatGPT용 Genie 플러그인, Unity Gateway를 거친 Codex, Model Serving 기반 커스텀 에이전트입니다. Codex 패턴에서는 개발자가 사내 자격 증명으로 로그인합니다. OpenAI 키는 게이트웨이에만 두고 모든 요청을 기록하며, 팀별 예산과 작업별 모델을 지정합니다.
- **적용 팁:** 벤더와 무관하게 쓸 수 있는 원칙입니다. 원본 API 키를 개발자 PC에 두지 말고 프록시나 게이트웨이에서 주입하세요. 팀별 예산과 감사 로그를 처음부터 켜 두세요. 위 Cursor 사고와 같은 키 유출 피해도 줄어듭니다.
- 🔗 [Databricks Blog](https://www.databricks.com/blog/openai-and-databricks-enterprise-ai-your-governed-data)

### 마감 임박: OpenAI Evals·Agent Builder·`/v1/prompts` 11/30 종료
- 공식 지원 중단 페이지 기준으로 세 기능 모두 11/30에 종료됩니다. 권장 대안은 다음과 같습니다. Evals는 Promptfoo로 옮기고, Agent Builder는 Agents SDK나 ChatGPT Workspace Agents로 바꾸고, 재사용 프롬프트 내용은 애플리케이션 코드로 옮깁니다. ChatKit은 유지됩니다.
- **적용 팁:** 이번 주 안에 eval 데이터셋과 grader를 내보내 저장소에 커밋하세요. 프롬프트도 코드와 함께 버전 관리하세요.
- 🔗 [OpenAI Deprecations](https://developers.openai.com/api/docs/deprecations)

## ⚙️ LLM 서빙/인프라
- **llama.cpp v1.0.0 (11/13):** `libllama`와 `libggml`이 1.0이 됐습니다. 앞으로 `include/`의 공개 C API를 깨는 변경은 메이저 버전에서만 한다는 semver 규칙을 약속했습니다. 아키텍처 변형 150개 이상을 지원합니다. 바인딩이나 앱을 얹어 쓴다면 이제 버전을 고정해 업그레이드하기 쉬워졌습니다. 🔗 [Hugging Face Blog](https://huggingface.co/blog/ggml-org/llama-cpp-v1)
- **AgentCore Runtime V2 스냅샷 패턴 (AWS, 11/13):** 컨테이너를 한 번 초기화해 microVM 스냅샷을 만들고 세션마다 복원합니다. 세션 시작이 빨라지고 쓰지 않는 메모리는 과금되지 않습니다. 대신 배포마다 몇 분이 걸립니다. 권장 패턴은 세 가지입니다. 초기화는 모두 `app.run()` 전에 하고, 무거운 파일은 빌드 훅에서 미리 준비하고, 사용자가 채팅창을 열 때 세션을 미리 띄우세요. 스냅샷 전에는 네트워크 연결을 닫아야 합니다. 🔗 [AWS ML Blog](https://aws.amazon.com/blogs/machine-learning/architecture-patterns-for-fast-session-startup-on-amazon-bedrock-agentcore-runtime)
