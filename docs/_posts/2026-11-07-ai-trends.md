싼 모델이 1차로 판정하고, 확신이 낮은 건만 비싼 모델에 넘기세요. 에이전트는 커널을 공유하지 않는 격리 환경에서 돌리세요.

## 🎯 활용 Best Practice

### 계층형 LLM 심사: 애매한 것만 Opus에게 (Hightouch)
- Hightouch는 1,000개 신원 레코드에서 "서로 다른 사람이 하나로 잘못 합쳐진 경우"를 LLM으로 판정했습니다. 쉬운 세트 기준으로 Opus 5.5 단독은 99.0%에 $3.86이었습니다. 소형 모델 Jev가 먼저 판정하고 확신도 30~90% 구간만 Opus에 넘기는 방식은 98.8%에 $0.88이었습니다.
- 어려운 세트에서도 이 하이브리드는 95.3%로 Opus 단독(95.1%)과 비슷했고, 비용은 약 45% 적었습니다. 제목의 "4배"는 쉬운 세트 기준입니다.
- 단독 정확도가 더 높았던 GPT-6 Luna는 하이브리드에서 오히려 약했습니다. 높은 확신으로 틀리는 경우가 있었기 때문입니다.
- **적용 팁:** ① 1차 모델은 정확도보다 **보정(calibration)** 을 보고 고르세요. ② 컷오프를 50%로 고정하지 말고 직접 실험해 정하세요. ③ 프롬프트에는 실제 오류 사례를 넣으세요. 모든 모델에서 효과가 가장 컸습니다.
- 🔗 [Hightouch Blog](https://hightouch.com/blog/llm-judges-identity-resolution)

### 에이전트 샌드박스는 컨테이너에서 microVM으로 (Replit)
- Replit은 에이전트 실행 환경을 커널을 공유하는 컨테이너에서 KVM 기반 microVM으로 바꿨습니다. 6월 1일부터 11월 4일까지 감사한 Linux CVE 6,211건 중 96.1%를 피했고, 샌드박스 할당에는 약 500ms가 걸린다고 합니다(자사 수치).
- **적용 팁:** ① API 키는 샌드박스 안에 두지 말고, 바깥의 브로커가 붙이게 하세요. ② egress 필터와 DNS 제어는 게스트가 아니라 호스트에서 적용하세요. ③ npm·pip 레지스트리 방화벽으로 악성 패키지를 막으세요.
- 🔗 [Replit Frontier](https://frontier.replit.com/sandbox-engine-microvms-part-1/)

### 커넥터는 "URL"이 아니라 "OAuth 클라이언트"로 묶어라 (ChatGPT 사례)
- 같은 MCP 서버를 가리키는 커넥터 두 개를 쓰는 대화에서, 후속 tool call이 사용자에게 알리지 않은 채 다른 커넥터로 넘어갔다는 신고가 나왔습니다. 일회용 확인 코드가 앱 A에서 발급되어 앱 B로 전달됐습니다. 서버가 코드를 OAuth 클라이언트에 묶어 두었기 때문에 이 요청은 거부됐습니다. OpenAI의 공식 답변은 아직 없습니다.
- **적용 팁:** MCP 서버를 만든다면 확인 코드나 대기 중인 작업을 발급한 클라이언트 ID에 묶고, 다른 클라이언트에서 쓰려 하면 거부하세요. 이 사례에서 피해를 막은 것도 이 장치였습니다.
- 🔗 [OpenAI 개발자 포럼](https://community.openai.com/t/security-follow-up-tool-call-silently-routed-to-a-different-connector/1413053)

### 긴 세션은 자동 압축보다 "핸드오프"가 낫다는 경험담
- 자동 압축(autocompaction)에 맡기기보다 작업 상태를 문서로 정리해 새 세션에 넘기는 편이 낫다는 사용자 경험이 공유됐습니다. 공식 가이드가 아닌 커뮤니티 의견입니다.
- **적용 팁:** 큰 작업 단위가 끝날 때마다 "목표·완료·남은 일·주의점"을 HANDOFF.md에 적게 하고, 새 세션은 그 파일을 읽고 시작하게 하세요.
- 🔗 [Latent Space AINews](https://latent.space/p/ainews-inkling-2-small-17a-594b-trained-in-68-hours-on-12t-tokens-beating-muse-spark/) (Reddit 글을 인용한 2차 정리)

### 에이전트 메모리는 "계층 + 드리밍"으로 (Anthropic, 11/6)
- Anthropic 엔지니어링 블로그가 에이전트 메모리를 다섯 층으로 정리했습니다. 전체 기록(transcript), 세션 중 메모, 위키 같은 구조화 표현, 매 세션 주입되는 작은 컨텍스트, 그리고 오프라인에서 메모를 정리하는 "드리밍(dreaming)"입니다.
- CL-Bench DB 과제에서 Opus 5.5는 메모리를 쓰자 0.655에서 0.838로 올랐습니다. 약 35만 파일 코퍼스에서는 위키+검색 조합이 61%로, 검색만 쓴 경우(53%)보다 높았고 질문당 약 2만 토큰을 아꼈습니다.
- 강한 모델은 "실패만 기록하라" 같은 고정 규칙을 주면 오히려 성능이 떨어졌습니다. 약한 모델(Sonnet 4.6)은 "답하기 전에 메모리를 읽어라"는 명시적 지시가 효과적이었습니다.
- **적용 팁:** ① 프롬프트에는 메모리의 *목적*만 적고 방법은 모델 판단에 맡기세요(약한 모델은 예외). ② 화면·파일에서 다시 읽을 수 있는 상태는 적지 말고, 검증된 전략·규칙만 남기세요. ③ 항상 로드되는 MEMORY.md는 짧게 두고 세부는 하위 페이지로 링크하세요. ④ 여러 에이전트가 한 파일에 동시에 쓰지 않게 페이지를 나누고, 주기적으로 메모를 원본 기록과 대조해 고치세요.
- 🔗 [Anthropic Engineering](https://www.anthropic.com/research/components-of-agent-memory)

### 팀 규칙은 "스킬"로 주고, 숨은 테스트로 확인하라 (Show HN)
- 한 개발자가 백엔드 과제 15개에서 코딩 에이전트 스킬의 효과를 숨은 테스트로 측정했습니다. 재고 5개에 구매자 20명이 몰리는 경우, 다른 사용자 주문 조회, 배포 중 구버전 앱과 새 스키마 공존 같은 상황입니다.
- 스킬이 없을 때는 150회 중 25회가 치명적 실수였고, 스킬을 쓰자 2회로 줄었습니다(Sonnet 5.5·Haiku 5.5, 과제당 5회). 다운 마이그레이션·API 문서 같은 팀 규칙 누락도 30건에서 4건으로 줄었습니다. 작성자 자체 수치이며 검증되지 않았습니다.
- **적용 팁:** 동시성·권한·무중단 마이그레이션처럼 "모델이 알아도 자주 빠뜨리는" 규칙을 스킬 파일로 만드세요. 효과는 에이전트에게 보이지 않는 테스트로 재야 과대평가를 피할 수 있습니다.
- 🔗 [GitHub: backendskills](https://github.com/globalmpc/backendskills)

## 🤖 새로운 모델
- **Inkling 2 Small (Thinking Machines, 11/5):** 594B 파라미터(활성 17B) MoE 모델로, 지금은 Tinker에서만 쓸 수 있습니다. 주 사전학습 단계(8.4T 토큰, NVFP4)에 68시간이 걸렸습니다. 외부 안전성 테스트를 마친 뒤 "다음 주" Apache 2.0으로 가중치를 공개할 예정입니다. 🔗 [Thinking Machines](https://thinkingmachines.ai/news/inkling-2-small/)
- **Gemini Omni 1.2 Flash (11/5):** 최대 15초 영상 생성과 대화형 편집을 지원합니다. 720p 기준 초당 $0.07로, 이전 버전보다 30% 저렴합니다. 정식 출시(GA) 상태입니다. Google은 저해상도로 초안을 만든 뒤 업스케일하는 순서를 권합니다. 🔗 [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemini-omni-1-2-flash/)
- **Arete-27B (Nous Research):** Qwen3.8-27B를 SFT만으로(약 5,280만 토큰) 후학습해, 정치적으로 민감한 질문에서 회피·선전성 답변을 줄인 모델입니다. 자체 Propaganda_Eval에서 선전성 답변 비율이 22%에서 약 1%로 줄었고, Hermes Bench는 기본 모델과 비슷했습니다(65.60% 대 65.77%). 가중치는 Hugging Face에 공개됐고, 라이선스는 글에 명시되어 있지 않습니다. 🔗 [Nous Research](https://nousresearch.com/arete)
- **후속·미확인:** GPT-6.2 출시가 임박했다는 소문은 계속 나오지만, 공식 발표는 아직 없습니다.

## ⚙️ LLM 서빙/인프라
- **CMU ServerBench:** 코딩 에이전트에게 서빙 스택을 직접 만들게 한 실험입니다. Sonnet 5.5가 만든 최고 시스템은 GPU 1달러당 가치가 vLLM의 4.87배였습니다. 다만 검증을 통과한 결과는 33회 중 22회였습니다. 🔗 [Latent Space AINews](https://latent.space/p/ainews-inkling-2-small-17a-594b-trained-in-68-hours-on-12t-tokens-beating-muse-spark/) (2차 정리)
- **엔드포인트 품질 편차:** Artificial Analysis에 따르면 서버리스 엔드포인트 100여 개 중 약 4분의 1이 기준 배포보다 점수가 낮습니다. 같은 오픈 모델이라도 공급자를 바꿀 때는 eval을 다시 돌리세요. 🔗 [Latent Space AINews](https://latent.space/p/ainews-inkling-2-small-17a-594b-trained-in-68-hours-on-12t-tokens-beating-muse-spark/) (2차 정리)
