## 📌 오늘의 한 줄 요약
에이전트에게 "코드를 써라"가 아니라 **"불변 조건을 지키며 부수고 고쳐라"**를 맡기는 사례가 나왔습니다. 핵심은 텔레메트리 접근, 명시한 불변 조건, 되돌리기 어려운 변경에 대한 사람 승인입니다.

## 🎯 활용 Best Practice

### 출시 전 "카오스 루프": 에이전트가 부수고 고친다 (Anthropic, 11/17)
- Claude Docs 출시 2주 전부터 Claude가 운영 환경을 복제한 staging을 하루 100만 건 이상의 합성 문서로 돌렸습니다. "시나리오 실행 → 텔레메트리 읽기 → 수정안 → staging 배포"를 반복했습니다. 시나리오에는 하루 1,000만 문서 생성, 연결 2.2만 개 동시 재접속, 부하 중 서버 강제 종료, DB 지연이 있었습니다.
- 출시 후 약 20억 요청 중 서버 오류는 60건, 롤백은 0건이었습니다. 메모리 문제를 고쳐 예상 pod 수가 500개 이상에서 약 50개로 줄었습니다. 리허설한 시나리오 10개 중 7개가 실제로 일어났습니다. 추론 비용은 정가 기준 약 $125,000이고, 그중 절반은 낭비였다고 작성자가 직접 추정합니다.
- 메모리 사례도 있습니다. 문서 하나가 3GB를 썼는데, 첫 수정(캐시 축소)은 원인이 아니라서 버렸습니다. 세밀하게 프로파일링해 보니 키 입력마다 문서가 여러 번 복사되고 있었고, copy-on-write로 바꾸자 약 180MB까지 내려갔습니다.
- **적용 팁:**
  - 관측 도구의 MCP 서버를 연결해 에이전트가 텔레메트리를 직접 읽게 하세요.
  - "문서는 즉시 열린다", "확인 응답한 편집은 사라지지 않는다"처럼 **불변 조건을 글로 적어** 먼저 넘기세요.
  - 스키마·저장 구조처럼 되돌리기 어려운 변경은 사람 승인을 거치게 하고, 쉽게 되돌릴 수 있는 변경만 자동 배포하세요.
  - 쿼리마다 "스캔한 행 수 대비 반환한 행 수"를 기록하는 식으로, 에이전트가 원인을 추적할 수 있게 계측하세요.
  - 작은 서비스라면 2주에 $3,000~10,000 정도로 추정합니다(작성자 추정, 미검증).
- 🔗 [Claude Blog](https://claude.dev/blog/chaos-loop-claude-docs-launch/)

### 감사 업무에 에이전트 100여 개: KPMG UK 실험 (11/18 보도)
- FTSE 250 기업 한 곳의 감사에 에이전트 100여 개가 사람 팀과 함께 참여했습니다(개발 약 4개월). 데이터 수집·분석, 문서화, 결론 초안 작성을 맡았고, 몇몇 경우에는 사람보다 더 깊이 파고들어 질문을 던졌다고 합니다.
- 한계도 분명했습니다. 규제 요건을 회사 문서와 잘못 대응시킨 에이전트가 있어 감사인이 개입했고, 데이터 품질이 가장 큰 장애물이었습니다. 정식 법정 감사는 아니었으며, 비교 수치도 공개되지 않았습니다.
- **적용 팁:** 고위험 업무에 에이전트를 쓸 땐 "규정 ↔ 증빙 대응" 같은 판단 단계에 사람 검토를 고정으로 두세요. 도입 전에는 입력 데이터부터 정리하세요.
- 🔗 [European Business Magazine](https://europeanbusinessmagazine.com/ai-agents-better-questions-kpmg/) (FT 보도를 인용한 2차 보도, 1차 자료 미확인)

### AI 전면 재작성의 함정: curl의 Rust 재작성 (Daniel Stenberg, 11/17)
- 에이전트가 curl의 C 코드 약 18.5만 줄을 Rust 약 34만 줄로 옮긴 프로젝트들이 등장했습니다. 그런데 같은 3주 남짓 동안 원본 curl에는 커밋 300개 이상이 머지됐고, 그중 버그 수정이 200개 이상이었습니다.
- 2026년 curl 취약점 81건 중 메모리 안전 언어였다면 막았을 법한 것은 14건(17.3%)이었습니다.
- **적용 팁:** AI 재작성의 비용은 변환이 아니라 **이후 유지보수 속도를 따라잡는 것**입니다. 재작성을 하겠다면 "어떤 결함을 몇 % 줄이는가"를 먼저 수치로 정하고, 원본과 동기화하는 계획까지 세우세요.
- 🔗 [daniel.haxx.se](https://daniel.haxx.se/blog/2026/11/17/actual-curl-rewrites-in-rust/) · [Simon Willison](https://simonwillison.net/2026/Nov/18/daniel-stenberg/)

### LLM으로 리버스 엔지니어링할 때의 작업 루프 (개인 블로그, 11/18)
- 이 글은 Ghidra MCP 브리지와 radare2를 붙여 에이전트가 바이너리를 분석하게 합니다.
- 먼저 발견한 내용을 Markdown 파일에 계속 적게 합니다. 컨텍스트가 압축되거나 작업을 넘겨도 이어서 할 수 있고, 같은 곳을 맴도는 것도 막아 줍니다.
- 막히면 가설을 CSV에 적고 → 실험을 설계하고 → 결과를 기록하는 "가설 디버깅" 스킬을 씁니다.
- **적용 팁:** 탐색형 작업(디버깅·분석)에서는 노트 파일과 가설 기록을 에이전트에게 강제하세요. 무작위로 추측하는 것을 크게 줄일 수 있습니다.
- 🔗 [Slow Chronicle](https://www.slowchronicle.com/posts/llm-assisted-reverse-engineering)

## 🤖 새로운 모델

### Gemini 4 Neon (Google, 11/18)
- Carbon(고난도 장기 작업)과 Hydrogen(빠른 일상 작업) 사이에 놓인 모델입니다. 가격은 100만 토큰당 입력 $3, 캐시 입력 $0.15, 출력 $15이고, 컨텍스트는 100만 토큰입니다.
- Google 발표 기준으로 Terminal-Bench 4.1 65.2%, Artificial Analysis Coding Agent Index 1위(58.6)입니다. Antigravity에서는 병렬 서브에이전트를 지휘하는 오케스트레이터로도 쓰입니다. 독립 검증은 아직 없습니다.
- 🔗 [Google Blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

### DaisyRose-27B: 실패 유형을 겨냥한 에이전트 RL (RadixArk, 11/18)
- Qwen3.8-27B를 장기 에이전트 과제 1,200개로 강화학습해 Terminal-Bench 4.1 pass@1을 5.6%에서 12.0%로 올렸습니다. 과제는 **기본 모델이 실제로 틀리는 지점**을 겨냥했고, 해결률은 중간 수준이 되도록 맞췄으며, 보상 해킹이 없는지 점검했습니다.
- 학습에는 H200 144장으로 18일이 걸렸고, 체크포인트는 Hugging Face에 공개됐습니다(라이선스는 모델 페이지에서 확인 필요).
- 🔗 [RadixArk Blog](https://www.radixark.com/blog/daisyrose-27b)
