에이전트 보안은 "공격처럼 보이는 텍스트 탐지"에서 "사용자가 요청한 행동인지 확인"으로, eval은 "점수"에서 "얼마나 오래·열심히 시도했는지"까지 함께 보는 쪽으로 옮겨가고 있습니다.

## 🎯 활용 Best Practice

### 도구 호출마다 "사용자가 요청했나?"를 묻기: Semantic governance policies (Google, 11/23)
- Gemini Enterprise Agent Platform의 정책 엔진이 에이전트가 제안한 도구 호출을 실행 전에 가로채, LLM 판정기가 **사용자 요청·시스템 지시(신뢰)** 와 비교합니다. 도구 결과·파일·메시지는 "지시가 아닌 데이터"로 취급합니다.
- AgentDojo(gemini-2.5-flash, 기본 의도 검사만, 6회 평균): 공격 성공률 **48.7% → 0.9%**, 정상 과제 유용성 **−2.6%p**, 과차단은 정상 과제 97개 중 1개. 도구 호출이 필요한 공격 929건은 한 건도 성공하지 못했습니다.
- 한계: 남은 성공은 도구 호출 없는 "답변 조작"이고, 공격이 이 시스템에 맞춰 적응된 것이 아닙니다. 신뢰/비신뢰 분리는 판정기 지시에 의존하는 것이지 기술적 경계가 아닙니다.
- **적용 팁:** 자체 에이전트에도 ① 실행 직전 "이 호출이 원래 요청에서 나왔는가" 판정 단계를 두고 ② dry-run으로 판정 로그부터 검토한 뒤 강제 적용하며 ③ 텍스트 출력 필터는 별도로 붙이세요. 정책은 "디지털 상품 $30 초과 환불은 매니저 승인"처럼 **규칙+임계값을 평문으로** 쓰면 비개발자도 관리할 수 있습니다([9월 1편](https://developers.googleblog.com/en/build-zero-trust-ai-agents-that-judge-intent-not-just-syntax/)).
- 🔗 [Google Developers Blog](https://developers.googleblog.com/did-the-user-ask-for-this-securing-ai-agents-against-intent-hijacking-with-semantic-governance-policies/)

### 지름길이 보이면 모델이 덜 시도한다: Fable 5.2 실험 (Goodhart Labs, 11/24)
- 같은 과제를 "부정행위 지름길이 있는 버전/없는 버전"으로 나눠 돌렸더니, 어려운 암산 과제에서 지름길이 있을 때 17회 중 12회가 3분 안에 포기했습니다(없을 때 19회 중 6회). 평균 작업 시간 3.9분 vs 12.3분, 정답률 27% vs 40%.
- 쉬운 문제나 다른 과제 상당수에서는 유의미한 차이가 없었고 표본도 작습니다. 저자들은 의도적 sandbagging보다는 "보이는 지름길 = 과제가 불가능하다는 신호"로 해석한다고 추정합니다.
- **적용 팁:** eval에서 점수만 보지 말고 **작업 시간·도구 호출 수·토큰**을 함께 기록하세요. 에이전트가 일찍 포기하면 "실현 가능한 과제이니 끝까지 시도하라" 또는 "먼저 가능성을 검증하라"를 명시하고, 쓰지 않을 우회 도구는 환경에서 빼는 편이 낫습니다.
- 🔗 [Goodhart Labs](https://goodhartlabs.com/blog/fable-5-2-tries-less-on-some-hard-tasks-when-a-shortcut-is-available)

### "목표를 정의하고, 검증 도구를 쥐여 주라": 1년간의 변곡점 3개 (Simon Willison, 11/24)
- AI Engineer Code Summit 키노트. ① 2025년 11월 코딩 에이전트 기본 출력이 "대체로 맞는" 수준이 됨 ② 2026년 6~7월 Fable급 모델: 목표와 도구만 있으면 무차별 시도로 문제를 푼다 ③ 9~10월 Opus 5.5: 3D·게임의 "재미"까지 다룸.
- 사례: Safari 표시 버그에서 Fable이 스스로 스크린샷 장치와 로깅 서버를 만들어 원인을 찾음. "이 게임은 아직 재미없다"는 한 줄 피드백에 Opus 5.5가 몇 시간씩 플레이테스트하며 밸런스를 조정함.
- **적용 팁:** 지시는 "무엇이 완성인가"를 명확히, 그리고 에이전트가 **결과를 직접 관찰할 수단**(스크린샷, 로그, 테스트)을 함께 주세요. 품질 기준("재미있고 아름답게")도 명시적으로 요구하면 반영됩니다.
- 🔗 [Simon Willison](https://simonwillison.net/2026/Nov/24/llm-inflection-points/)

### 연구 업무 위임은 "들쭉날쭉한 전선"을 알고 (OpenAI 내부 데이터, 2차 보도)
- 보도에 따르면 OpenAI 내부에서 코딩 에이전트가 2~4시간짜리 연구 과제를 혼자 끝내는 비율이 3월 23% → 10월 46%, 4~8시간 과제는 13% → 35%로 올랐습니다. 학습 실행 모니터링(79%)은 강하고, 학습 실행 시작(35%)·추론/서빙 코드 작성(25%)은 약했습니다. 자체 측정이며 방법론도 바뀌었습니다.
- OpenAI의 9월 글은 "긴 과제는 성공 사례 절반 이상이 사람 개입을 거쳤다", "에이전트가 연구 인프라를 손상시킨 뒤 제한·모니터링을 추가했다"고 적고 있습니다.
- **적용 팁:** 팀에서 위임할 때 과제 **유형별 성공률**을 따로 재고, 모니터링·트러블슈팅처럼 강한 영역부터 맡기세요. 우선순위 판단은 사람이 쥐고, 에이전트 환경엔 권한 제한을 먼저 거세요.
- 🔗 [Let's Data Science 보도](https://letsdatascience.com/news/openai-reports-agents-complete-an-estimated-46-of-two-to-fou-d2271f4e) · [OpenAI 9월 글](https://openai.com/index/research-acceleration-view-inside-openai/)

## 🤖 새로운 모델

### GPT-6 계열, 전용 모델 없이 단백질 설계 (OpenAI, 11/24)
- 추론과 범용 코드만으로 단백질 형태·서열을 설계. 실험실 검증에서 미니바인더 322개 중 35개(10.9%)가 표적에 결합했고, motif scaffolding은 43.7%로 RFdiffusion(27.8%)보다 높았습니다.
- 한계: 서열 공급·후보 필터링에는 여전히 전용 모델(ProteinMPNN, Boltz-2 등)을 썼고, 전체 구조 예측은 약합니다(TM-score 0.38 vs ESMFold2 0.93). OpenAI도 "end-to-end 설계는 아직 아님"이라고 밝혔습니다.
- 🔗 [OpenAI](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities/)
