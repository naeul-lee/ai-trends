## 📌 오늘의 한 줄 요약
에이전트는 '할 수 있는 일'이 아니라 '선언한 의도' 안에서만 움직이게 하고, eval은 채점기부터 사람과 맞춰 본 뒤 신뢰구간과 함께 보고하세요.

## 🎯 활용 Best Practice

### eval은 "질문 → 구성개념 → 채점기 검증" 순서로 (Anthropic, 11/13)
- Anthropic이 안전성 eval을 만들며 얻은 교훈 13가지를 정리했습니다. 단일 턴 평가는 최신 모델에서 무해 응답률이 94~98%로 포화됐습니다. 그래서 대화 중 한 턴이라도 나쁘면 실패로 보는 멀티턴 평가를 권합니다.
- 설정 차이가 결과를 크게 흔들었습니다. 같은 모델이 API와 claude.ai 설정에서 최대 34%p 차이가 났습니다. 98% 대 94%처럼 보이는 차이도 통계적으로 유의하지 않아 우열을 가리지 못한 사례가 있었습니다.
- **적용 팁:** ① 채점 기준은 예/아니오 원자 항목으로 쪼개세요. ② 채점기와 전문가의 일치도를 전문가끼리의 일치도(Cohen's kappa)와 비교하세요. ③ 지표와 임계값은 결과를 보기 전에 적어 두세요. ④ 문항은 멀티턴 100개 이상, 단일 턴 1,000개 이상을 잡으세요. ⑤ 두 모델은 같은 문항으로 짝지어 비교하고 신뢰구간을 함께 보고하세요. ⑥ 해로운 요청과 같은 분야의 무해한 요청을 짝지어 넣어 "다 거절하는 모델"이 높은 점수를 받지 못하게 하세요.
- 🔗 [Anthropic](https://www.anthropic.com/research/building-strong-safety-evaluations)

### 에이전트 권한은 "의도 단위"로 선언하라 (Uber, InfoQ 11/15 보도)
- Uber는 신원·권한 확인만으로는 "이 행동이 지금 맥락에 맞는가"를 판단할 수 없다고 봤습니다. 그래서 에이전트마다 소유자, 페르소나, 허용 의도(intent), 제약, 위험 등급을 레지스트리에 등록합니다. 실행 중에는 훅이 중요한 지점마다 AI Guard에 판정을 받은 뒤에만 행동을 진행합니다.
- 가장 효과적인 완화책은 "가장 화려하지 않은 것", 즉 명시적인 의도·제약으로 범위를 좁히는 것이었다고 합니다. 모두에 같은 임계값을 쓰면 실패했고, 섀도 모드와 트래픽 재생으로 에이전트별로 보정해야 했습니다. 지연을 줄이려고 판정은 로컬의 작은 모델들을 병렬로 돌려 처리했습니다.
- **적용 팁:** 사내 에이전트마다 "허용 의도 목록 + 금지 조건" 한 장을 만들고, 도구 호출 직전 훅에서 이를 검사하세요. 새 정책은 바로 차단하지 말고 기록된 실행을 재생해 오탐부터 확인하세요. 외부 MCP 서버도 같은 정적 검사를 거치게 하세요.
- 🔗 [Uber Engineering(원문, 11/6)](https://www.uber.com/us/en/blog/securing-ai-agents/) · [InfoQ](https://www.infoq.com/news/2026/11/uber-secure-ai-framework/)

### Windows 11, 어떤 코딩 에이전트를 쓰는지 집계 (개인 분석, 11/16)
- 한 개발자가 Windows 11의 진단 구성 요소를 분석해, Claude·Codex·Copilot·Cursor·Antigravity 같은 코딩 에이전트와 Node.js·Python·GCC 등의 실행 여부가 비트맵으로 기록된다고 보고했습니다. 프롬프트나 소스 코드는 보지 못했다고 합니다. 이 데이터는 "선택적 진단 데이터"를 허용했을 때 업로드 대기열에 들어갑니다. 저자가 미국 지역에서 새로 설치했을 때는 이 옵션이 기본으로 켜져 있었습니다.
- 모든 설치본에서 켜져 있는지는 확인되지 않았습니다. Microsoft의 공식 입장은 아직 없습니다.
- **적용 팁:** 회사 PC 정책상 도구 사용 정보가 민감하다면 설정 → 개인 정보 및 보안 → 진단 및 피드백에서 "선택적 진단 데이터 보내기"를 끄세요. 관리 대상 기기라면 그룹 정책으로 일괄 적용하세요.
- 🔗 [xusheng.dev](https://xusheng.dev/posts/windows-coding-agent-telemetry/)

### AI가 쓴 Rust 코드는 테스트 대신 "증명"으로 (Harmonic Aristotle, 11/16)
- Harmonic의 Aristotle이 Rust 검증을 지원합니다. `unsafe` 블록을 포함해 정의되지 않은 동작이 없고 코드가 스펙대로 동작함을 증명합니다. C를 Rust로 옮길 때 원본과 동작이 같은지도 확인합니다.
- Solana 오더북 Manifest에서 28개 성질을 증명했고, 그 과정에서 반올림 버그를 찾아 수정됐습니다. 셀프서비스 사용량 과금으로 바로 쓸 수 있습니다.
- **적용 팁:** 에이전트에게 C→Rust 이식이나 금융 로직을 맡긴다면, 사람은 "증명할 성질(불변식)"을 먼저 적고 검증기를 CI 게이트로 거세요. 사람이 무엇을 증명할지 정하고 에이전트가 증명하는 분업이 계속 나오고 있습니다.
- 🔗 [Harmonic](https://www.harmonic.fun/news/aristotle-rust-verification/)

### 브라우저를 에이전트에 빌려줄 땐 "핸드오프"를 기본값으로 (OpenCode Browse)
- OpenCode Browse는 코딩 에이전트가 MCP로 실제 브라우저의 탭과 로그인 세션을 쓰게 하는 오픈소스 확장입니다. 로그인, 2FA, 결제 단계에서는 탭을 사람에게 넘기고, "Continue"를 눌러야 재개합니다. 공유할 탭과 허용 사이트도 사람이 지정합니다. 정확한 공개일은 페이지에 나와 있지 않습니다.
- **적용 팁:** 어떤 브라우저 에이전트를 쓰든 ① 전용 프로필을 쓰고 ② 허용 도메인을 제한하고 ③ 인증·결제는 반드시 사람이 넘겨받게 설정하세요.
- 🔗 [OpenCode](https://opencode.ai/product/browse)

## 💰 수익화

### 기업이 "에이전트 손님"을 받는 표준: Poppy 1.0 (Sierra, 11/13)
- Sierra가 Meta와 만든 Personal Agent Protocol(Poppy) 1.0을 냈습니다. 기업은 방문한 개인 에이전트가 누구인지 확인하고, 무엇을 할 수 있는지(주문 조회, 예약 등)를 선언합니다. MCP·OpenAPI·OAuth 위에 만들었습니다. Shopify는 모든 상점에 Poppy를 켰고, Meta의 Muse 에이전트는 방문하는 사이트마다 Poppy를 먼저 찾습니다. 스펙은 아직 초안 단계입니다.
- 지난주 United가 제3자 에이전트의 대리 예약을 막은 것과 대조됩니다. 막을지, 조건을 걸고 받을지 기업마다 선택이 갈리고 있습니다.
- **적용 팁:** 커머스·예약 서비스라면 에이전트에 허용할 행동과 사람 확인이 필요한 행동을 먼저 분류하세요. 공식 구현 키트의 검증기로 시작해 보세요.
- 🔗 [Sierra](https://sierra.ai/blog/releasing-poppy) · [TNW(2차)](https://thenextweb.com/news/sierra-poppy-1-0-shopify-meta-muse-personal-agents)
