## 📌 오늘의 한 줄 요약
**에이전트가 "다 했다"고 해도, 그 커밋과 그 요청이 실제로 어디까지 갔는지는 기계로 확인하라.** 자격 증명, 추론 제공자, 요구사항 모두 해당합니다.

## 🎯 활용 Best Practice

### 코딩 에이전트가 커밋한 키 하나가 프롬프트 유출로 (Together AI, 11/21)
- 공개 저장소 xorl 개발 중 **AI 코딩 에이전트가 비공개 Hugging Face 저장소 접근 자격 증명을 커밋**했습니다. 자동 스캔이 감지해 커밋을 되돌렸지만, 노출된 사이에 외부인이 키를 써서 고객 프롬프트 샘플(6~7월 MiniMax M3·GLM-5.2·Kimi K2.6 요청 일부)을 내려받았습니다.
- 공격자는 내려받은 프롬프트에서 **다른 서비스의 자격 증명을 찾아 유효성까지 시험**했습니다. Together는 단기·범위 제한 자격 증명, 모든 PR의 자격 증명 검사, 신규 계정 ZDR 기본값, 코딩 에이전트 개발 절차 개편을 조치로 내놨습니다.
- **적용 팁:** ① "커밋 되돌리기"는 대응이 아닙니다. 노출된 키는 **즉시 폐기(rotate)** 하세요. ② 에이전트 작업 환경에는 장기 키를 두지 말고, push 전에 pre-commit 시크릿 스캔을 강제하세요. ③ 프롬프트에 키·토큰을 붙여 넣지 마세요. 프롬프트 로그도 유출 대상입니다.
- 🔗 [Together AI 공지](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026)

### "ZDR 표시"를 믿지 말고 검증하라: OpenRouter의 제공자 정리 (11/22)
- Dragos 연구진이 일부 추론 제공자에서 데이터 침해나 데이터 정책 미준수 정황을 찾았습니다. OpenRouter는 **제공자 3곳을 퇴출하고 엔드포인트 125개를 Zero Data Retention(ZDR) 대상에서 제외**했으며, 영향받았을 수 있는 고객에게 통보했습니다. OpenRouter 자체 침해는 아니라고 밝혔습니다.
- 앞으로는 연구진의 테스트를 상시 점검으로 돌리고, 요청이 제3자로 전달되는 네트워크 경로를 확인한 뒤에만 ZDR을 복원한다고 합니다.
- **적용 팁:** ① 라우터를 쓴다면 민감한 작업은 **허용 제공자 목록(allowlist)** 으로 고정하세요. ② 가장 싼 엔드포인트로 자동 라우팅하는 설정은 민감 데이터에 쓰지 마세요. ③ 직접 운영하는 서비스라면 가짜 자격 증명(canary)을 프롬프트에 심어 두고, 누군가 그걸 쓰는지 감시하는 방법을 고려하세요. 이번 사건도 그렇게 드러났습니다.
- 🔗 [OpenRouter 공지](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/) · [The Hacker News 보도](https://thehackernews.com/2026/11/openrouter-drops-3-providers-after.html)

### 테스트는 63% 통과, 과제 완료는 8% 미만: SWE-CoWork (arXiv, 11/15)
- 에이전트를 동료 26명(각자 일부 요구사항만 앎), 프로젝트 보드, 채팅 기록이 있는 가상 조직에 넣고 실제 저장소 101곳의 과제를 줬습니다. 상위 두 모델은 fail-to-pass 테스트를 약 63% 통과했지만 **과제 전체를 끝낸 비율은 8% 미만**이었습니다.
- 실패 원인은 요구사항 추적입니다. Claude Opus 5.5는 첫 질문의 93%를 맞는 담당자에게 했지만 동료가 가진 요구사항은 64%만 얻었습니다. "나중에 묻겠다"던 질문은 다시 묻지 않았고, **완료라고 보고한 요구사항의 31%가 테스트에서 실패**했습니다.
- **적용 팁:** ① 에이전트에게 요구사항을 **체크리스트 파일**로 주고, 항목마다 검증 테스트를 연결하세요. ② 인계 보고서는 믿지 말고 "보고된 완료 항목 = 통과한 테스트"인지 기계로 대조하세요. ③ 미해결 질문은 별도 목록으로 남기게 하고, 종료 조건에 "미해결 질문 0개"를 넣으세요.
- 🔗 [arXiv 2611.20218](https://arxiv.org/abs/2611.20218) · [The Decoder 보도](https://the-decoder.com/ai-coding-agents-ace-isolated-tests-but-complete-fewer-than-one-in-ten-tasks-in-a-simulated-workplace/)

### 작은 오픈 모델 여러 개 + 규칙 + 짧은 사람 검토 = 프런티어 모델보다 나은 라벨 (Explosion, 11/22)
- spaCy를 만든 Matthew Honnibal이 코딩 에이전트에게 NER 데이터 생성 파이프라인을 돌리게 한 방법을 공개했습니다. 오픈 모델 여러 개로 라벨을 달고, 반복되는 오류는 규칙으로 고치고, Dawid-Skene 합의 모델로 표를 모은 뒤, **애매한 스팬만 사람이 예/아니오로** 판단합니다.
- 사람 검토는 10~20분 걸렸고 최종 F1은 0.926(HN)·0.954(AG News)였습니다. GPT 5.6 Sol 단독보다 오류가 50~60% 적었고, 비용은 Sol의 약 1/25이었습니다. 단, **LLM만으로 만든 패널(0.831)은 가장 좋은 단일 모델(0.872)보다 낮았습니다.** 모델들이 같은 실수를 하기 때문입니다.
- **적용 팁:** 여러 LLM의 다수결을 쓸 때는 꼭 **성격이 다른 신호**(규칙·사전·소량의 사람 판단)를 하나 섞으세요. 반복되는 오류는 프롬프트를 늘리기보다 규칙으로 고치는 편이 쌉니다.
- 🔗 [Explosion 블로그](https://explosion.ai/blog/agent-consensus-ner)
