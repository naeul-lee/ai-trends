## 📌 오늘의 한 줄 요약
AI에게는 "주인 의식"을 주고, AI가 낸 결과물은 "찾은 개수"가 아니라 "고친 개수"로 재야 합니다.

## 🎯 활용 Best Practice

### 프롬프트에 "이 코드는 네 것"이라고 써라 (Anthropic, Fable 5.2 가이드)
- Fable 5.2는 코드 소유자를 밝히지 않거나 남의 코드라고 하면 기존 구조를 그대로 늘리는 경향이 있습니다. "이 코드베이스는 네 것이고, 설계는 네가 정하며, 앞으로도 네가 계속 만든다"고 쓰면 소규모 코딩 테스트에서 중복 코드 통합이 10% 미만에서 약 절반으로 늘었다고 합니다.
- **적용 팁:** 리팩터링을 원하면 시스템 프롬프트에 소유권 문장을 넣고, 반대로 최소 변경만 원하면 "기존 구조를 유지하라"를 명시하세요. 수치는 작은 과제 기준이니 자기 저장소에서 다시 재 보세요.
- 🔗 [Anthropic 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#say-who-owns-the-code) · [Simon Willison](https://simonwillison.net/2026/Nov/10/prompting-claude-fable-52/)

### AI 취약점 탐지는 "수정 건수"로 평가하라 (VulnCheck, Glasswing 7개월 점검)
- Project Glasswing 원장 기준(11/2) 발견 37,966건 중 공개 7,349건, 수정 217건, 중복 약 1,650건. 9/8 이후 발견은 11,813건 늘었지만 수정은 15건 늘었습니다. curl 사례에선 공개 보고 34건 중 19건이 취약점이 아니었고, 모델은 91.5%를 critical/high로 매겼지만 메인테이너 판단은 51.3%였습니다.
- **적용 팁:** AI 보안 스캐너를 도입할 땐 ① 사람 트리아지 후 보고 ② 심각도는 별도 기준으로 재산정 ③ 지표를 발견 수가 아닌 "수정·확인된 건수"로 잡으세요. (VulnCheck는 관련 상품을 파는 회사라는 점도 감안)
- 🔗 [VulnCheck](https://www.vulncheck.com/blog/anthropic-glasswing-november-update)

### 코딩 에이전트에 "최신 웹 표준" 스킬을 붙여라 (Chrome·Edge·Firefox·MDN)
- 에이전트가 2019년식 JS(예: hover를 JS로 구현)를 쓰는 문제를 막는 스킬/플러그인. 250개 웹 기능·203개 사용 사례를 담았고, 모델이 이미 잘 아는 내용은 eval로 확인해 빼서 토큰을 아꼈습니다.
- **적용 팁:** `npx modern-web-guidance@latest install` 로 설치하거나, `legacy-scan` 으로 기존 코드의 레거시 패턴부터 찾아보세요. Claude·Codex·Cursor·Gemini용 매니페스트가 있습니다.
- 🔗 [GitHub](https://github.com/GoogleChrome/modern-web-guidance)

### AI 코드가 취약해지는 4가지 신호 (개인 블로그, HN 351점)
- 얕은 테스트(커버리지만 높음), 불필요하게 복잡한 코드, 팀의 코드 이해도 하락, 리뷰 속도 초과. 도입 후 장애 증가·복구 시간 증가가 경고 신호라고 봅니다. (어제 소개한 "100% AI 코딩 1년" 사례의 연장선)
- **적용 팁:** 사용자 유형별 E2E 테스트와 에러 계측(analytics·에러 핸들링)을 머지 조건으로 걸고, 장애 수·MTTR을 도입 전후로 비교하세요.
- 🔗 [Evan X. Merz](https://evanxmerz.com/post/ai-usage-generates-a-fragile-codebase/)

### 사람은 "무엇을 증명할지", 에이전트는 "증명"을 (DeepMind AlphaProof Code)
- 여러 LLM 에이전트가 Lean 증명 600만 줄 이상을 만들어 Signal 암호 프로토콜의 컴파일된 코드를 약 4주 만에 형식 검증했습니다. 코드의 약 1%만 사람 검토로 넘겼고, 일부러 되살린 과거 버그 2개는 "안전하지 않음"을 증명해 냈습니다.
- **적용 팁:** 에이전트 출력은 기계 검증기(타입체커·테스트·증명기)가 확인하게 하고, 사람은 명세와 예외 1%에 집중하는 분업이 핵심입니다.
- 🔗 [Google DeepMind](https://deepmind.google/blog/introducing-alphaproof-code/)

## ⚙️ LLM 서빙/인프라

### 오픈 추론 엔지니어링 가이드 (Modelplane/Upbound)
- 프롬프트 캐시는 첫 불일치 토큰에서 끊기므로 시스템 프롬프트·도구 정의를 앞에, 사용자 입력은 뒤에. 양자화는 선형 가중치 → 활성값 → KV 캐시 순으로. 자사 테스트에선 vLLM→SGLang 전환이 단일 최대 개선이었다고 합니다.
- **적용 팁:** 한 번에 하나만 바꾸고 실제 트래픽으로 측정, 엔진 버전은 고정 후 업그레이드마다 재벤치.
- 🔗 [Modelplane](https://docs.modelplane.ai/guides/inference-guide)
