## 📌 오늘의 한 줄 요약
에이전트에게는 **스스로 정답을 확인할 수단**(실제 시스템으로 검증한 테스트, 기계가 검사하는 규칙)을 주고, 라우팅·정책 판단처럼 **답이 정해진 결정은 생성 대신 '결정 모델'** 에 맡기는 흐름이 뚜렷합니다.

## 🎯 활용 Best Practice

### 스펙 + "실제 시스템에서 통과한 테스트"를 먼저 줘라 (AWS Emulator, 11/11)
- AWS가 200여 개 서비스를 로컬에서 흉내 내는 `aws-emulator`를 공개했습니다. 에이전트가 Smithy API 모델을 스펙으로 삼아 고객 시나리오 테스트를 쓰고, **먼저 실제 AWS에서 통과하도록 테스트를 고친 뒤** 그 테스트를 통과할 때까지 에뮬레이터를 만들었습니다. 첫 3주 커밋은 29,684개였습니다.
- 병합 게이트(자동 검사), 보안 에이전트 여러 개의 적대적 리뷰, 손대면 안 되는 코드를 막는 결정적 규칙을 겹겹이 뒀고, 알려진 불일치는 `things-that-do-not-work` 폴더에 공개합니다.
- 반례도 있습니다. 검증 수단 없이 나흘 밤 혼자 돌던 재구현 작업이, 스펙과 테스트 환경을 준 뒤에는 약 2시간 만에 끝났다고 합니다.
- **적용 팁:** 레거시 재작성이나 목(mock) 서버를 맡길 때는 실제 시스템의 응답을 기록한 테스트부터 만드세요. 사람은 "무엇이 정답인가"와 병합 기준을 정하는 데 집중합니다.
- 🔗 [AWS Emulator and the Engineer's Job When Agents Write the Code](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html) · [GitHub](https://github.com/aws/aws-emulator) · [Simon Willison](https://simonwillison.net/2026/Nov/11/aws-emulator/)

### 라우팅·정책 검사는 "결정 모델"로 (Gemini Decisions API · HF)
- Google의 `gemini-decision-1`은 텍스트를 생성하지 않고 예/아니오, 선택(2~255개), 루브릭 점수에 대한 **확률과 신뢰도**만 돌려줍니다. 응답 지연은 150~250ms이고, 입력 하나에 질문을 최대 1,000개까지 붙일 수 있습니다. Hugging Face도 Transformers에 같은 형식의 `decision` 파이프라인을 붙였습니다.
- Google이 든 사례는 모델 계층 라우팅, 도구 선택, MCP 도구 안전 검사입니다.
- **적용 팁:** 지금 LLM에게 JSON으로 "분류해 줘"라고 시키는 곳(라우터, 가드레일, 컨텍스트 채점)부터 바꿔 보세요. 신뢰도가 낮은 건은 상위 모델이나 사람에게 넘기세요. `p > 0.9` 같은 임계값은 실제 결과로 주기적으로 다시 맞춰야 합니다.
- 🔗 [Google Blog](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/) · [Decision Models in Hugging Face](https://huggingface.co/blog/decision)

### 에이전트 조사 결과는 "선행 연구 검색"을 따로 검증하라
- 비전문가가 에이전트 48개로 라이다 영상 약 1,200km²를 타일 단위로 훑어 미등록 마야 유적을 찾았다고 보고했습니다. 그런데 11/11 추가 글에서, 이미 2025년 논문에 나온 곳이었고 에이전트가 문헌 조사에서 이를 놓쳤다고 정정했습니다. (HN 912점)
- 원시 포인트 클라우드에서 식생과 지면을 나눠 형태를 확인하는 검증은 잘 작동했습니다. 문헌 검색이 약한 고리였습니다.
- **적용 팁:** "새롭다", "아무도 안 했다"는 결론은 별도의 에이전트나 사람이 다른 검색 경로로 다시 확인하게 하세요.
- 🔗 [Pietro Miotti](https://pietromiotti.com/latest/maya-site) · [HN 토론](https://news.ycombinator.com/item?id=50452455)

### 기계가 검사할 수 있는 규칙은 AGENTS.md가 아니라 훅·CI로
- 커뮤니티에서 나온 주장입니다. 린터나 pre-commit, CI로 검사할 수 있는 규칙은 도구로 강제하고, `AGENTS.md`에는 판단이 필요한 지침만 남기자는 것입니다. 같은 주에 "에이전트가 검사를 통과했다고 했지만 Undo가 깨져 있었다"는 사례도 공유됐습니다.
- **적용 팁:** AGENTS.md를 훑어 "~하지 마라" 중 정규식이나 린트로 표현되는 줄을 골라 훅으로 옮기세요. 에이전트의 "통과" 보고는 CI 결과로만 인정하세요.
- 🔗 [Latent Space AINews](https://latent.space/p/ainews-mercor-750m-series-d-at-20b-valuation-3b-run-rate/) (Reddit·X 게시물을 모은 2차 정리) · [Reddit 원글](https://www.reddit.com/r/ChatGPTCoding/comments/1xro33q/if_a_rule_can_be_checked_by_a_machine_it_shouldnt/)

### OpenAI가 말하는 Codex 작업법: 로컬 → 클라우드 핸드오프
- AI Engineer Code Summit 발표 정리입니다. 클라우드 환경은 저장소 접근 범위부터 정해 한 번 만들어 두고 팀이 공유합니다. 로컬 작업을 클라우드로 넘겨 여러 작업을 격리된 인스턴스에서 병렬로 돌리고, 돌아와서 PR을 리뷰합니다. 쉬운 작업은 effort를 낮추라는 조언도 있었습니다.
- 발표자도 핸드오프 시 컨텍스트 차이 관리는 아직 어색하다고 인정했습니다.
- **적용 팁:** 병렬 작업은 "각자 격리 환경 + 결과는 PR로"라는 형식을 지킬 때만 리뷰 부담이 감당됩니다.
- 🔗 [Latent Space](https://latent.space/p/codex-work/) (발표 정리, 2차)

## ⚙️ LLM 서빙/인프라

### Huawei MACaQ: 텍스트·이미지·음성 공용 양자화 (Apache 2.0)
- llama.cpp용 2~4비트 GGUF, vLLM W4A4, Diffusers 등을 지원합니다. 저장소 설명에 따르면 122B 모델 양자화에 64분이 걸리고, Qwen3.8-27B W4A4에서 prefill이 2.33배 빨라졌습니다. 모두 자체 수치입니다.
- **적용 팁:** 기존 GGUF를 다시 정제하는 MACaQ-R은 일반 llama.cpp에서 바로 돌아가므로, 로컬 모델 품질을 같은 용량에서 비교해 보기 좋습니다.
- 🔗 [GitHub](https://github.com/huawei-csl/MACaQ) · [HN 토론](https://news.ycombinator.com/item?id=50458166)

### RAG 검색 가속: 쿼리 분포를 학습한 라우터 (Apple, ICML 2026)
- 고정된 키 DB에 맞춰 작은 신경망을 학습합니다. KeyNet은 쿼리를 다시 쓰는 방식으로 기존 IVF 인덱스 앞에 붙여 99% recall에서 최대 약 8배 빨라졌습니다(Natural Questions 기준).
- **적용 팁:** 질문 패턴이 안정적인 사내 검색이라면 인덱스를 새로 만들지 않고 FAISS 앞에 쿼리 변환기를 두는 방법을 검토해 볼 만합니다.
- 🔗 [Apple ML Research](https://machinelearning.apple.com/research/faster-retrieval)
