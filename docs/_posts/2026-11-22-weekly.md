> 이번 주(11/16~11/22) 일간 리포트에서 뽑은 실천 항목을 주제별로 묶었습니다. 자세한 내용과 출처는 각 일간 글에 있습니다.

## 1. 정답 기준부터 주고, 결과는 기계가 검증
- **자연어 문서보다 검증 가능한 계약(명세)을 주세요.** 벤치마크는 탐색용과 홀드아웃용으로 나눠 과적합을 확인하세요. ([11/21](/ai-trends/2026/11/21/ai-trends.html))
- **최적화보다 기준 오라클을 먼저 만드세요.** 모든 수치에 근거 리포트 링크를 붙이세요. ([11/21](/ai-trends/2026/11/21/ai-trends.html))
- **산출물이 너무 커서 사람이 다 읽을 수 없다면, 검토 대상을 "검증기와 검증기의 신뢰성"으로 바꾸세요.** 코드에서는 타입·속성 기반 테스트·형식 명세가 그 역할을 합니다. ([11/17](/ai-trends/2026/11/17/ai-trends.html), [11/21](/ai-trends/2026/11/21/ai-trends.html))
- **장기 작업은 작게 쪼개 1:1로 배정하고, 핵심 결과는 독립 실행 2회로 교차 확인하세요.** 알려진 정답을 재현하는지부터 점검하세요. ([11/20](/ai-trends/2026/11/20/ai-trends.html))
- **AI가 쓴 테스트는 mutation test로 확인하고, 검토 모델은 작성 모델과 다른 것을 쓰세요.** ([11/20](/ai-trends/2026/11/20/ai-trends.html))
- **앱을 실제로 띄워 핵심 흐름을 통과시키는 `verify` 단계를 커밋 전에 두세요.** "재시도 3회 후 사람에게" 규칙도 함께 두세요. ([11/18](/ai-trends/2026/11/18/ai-trends.html))

## 2. 운영 변경은 "불변 조건 + 사람 승인"
- **출시 전 staging에서 에이전트가 부수고 고치게 하되, 불변 조건을 글로 먼저 적어 주세요.** 되돌리기 어려운 변경만 사람이 승인하게 하세요. ([11/19](/ai-trends/2026/11/19/ai-trends.html))
- **운영 에이전트는 "감지 → 원인 → 수정 → 복제본에서 검증 → PR 승인" 순서로 설계하세요.** 검증한 변경과 적용할 변경이 같은지 확인하세요. ([11/22](/ai-trends/2026/11/22/ai-trends.html))
- **고위험 업무의 판단 단계에는 사람 검토를 고정으로 두세요.** 도입 전에는 입력 데이터부터 정리하세요. ([11/19](/ai-trends/2026/11/19/ai-trends.html))

## 3. 권한·키·도구는 게이트웨이 한곳에서
- **원본 API 키를 개발자 PC에 두지 말고 게이트웨이에서 주입하세요.** 팀별 예산과 감사 로그는 처음부터 켜 두세요. ([11/16](/ai-trends/2026/11/16/ai-trends.html))
- **도구는 필요한 묶음만 주고, "사용자 대리"와 "에이전트 자체" 자격 증명을 나누세요.** 쓰기 작업에는 승인 정책을 거세요. ([11/22](/ai-trends/2026/11/22/ai-trends.html))
- **권한은 "허용 의도 목록 + 금지 조건"으로 선언하고 도구 호출 직전 훅에서 검사하세요.** 새 정책은 기록된 실행을 재생해 오탐부터 확인하세요. ([11/17](/ai-trends/2026/11/17/ai-trends.html))
- **에디터 확장 버전을 고정하고 허용 목록으로 관리하세요.** 에이전트 세션에 붙여넣은 키는 유출된 것으로 보세요. ([11/16](/ai-trends/2026/11/16/ai-trends.html))

## 4. 격리: 실행 환경과 사용자 데이터
- **샌드박스는 5가지로 고르세요.** 격리된 파일시스템, 나가는 네트워크 허용 목록, 자원 상한, 재사용 여부, 커널 수준 격리입니다. ([11/18](/ai-trends/2026/11/18/ai-trends.html), [11/21](/ai-trends/2026/11/21/ai-trends.html))
- **브라우저 에이전트는 전용 프로필과 허용 도메인을 쓰고, 인증·결제는 사람이 넘겨받게 하세요.** ([11/17](/ai-trends/2026/11/17/ai-trends.html))
- **개인 데이터를 다루는 에이전트는 메모리와 인덱스를 사용자 ID로 강제 분리하세요.** "다른 사용자 데이터가 나오는가"를 회귀 eval에 넣으세요. ([11/21](/ai-trends/2026/11/21/ai-trends.html))

## 5. eval과 비용은 "성공 1건당"으로
- **채점 기준은 예/아니오 원자 항목으로 쪼개고, 채점기와 전문가의 일치도를 확인하세요.** 지표와 임계값은 결과를 보기 전에 정하세요. ([11/17](/ai-trends/2026/11/17/ai-trends.html))
- **"해결 여부"와 "질문 속 착각을 지적했는지"를 따로 채점하세요.** ([11/16](/ai-trends/2026/11/16/ai-trends.html))
- **모델을 바꾸면 하네스도 다시 재세요.** 비교는 "성공 1건당 비용"으로 하세요. ([11/18](/ai-trends/2026/11/18/ai-trends.html))
- **에이전트 수를 늘리기 전에 합격 기준, 예산 상한, 외부 행동 승인 게이트부터 설계하세요.** ([11/20](/ai-trends/2026/11/20/ai-trends.html))
- **추론 레벨은 기본값을 낮게 두세요.** 한 단계 올리면 비용이 6배가 된 사례도 있었습니다. ([11/22](/ai-trends/2026/11/22/ai-trends.html))
- **도구가 많으면 스키마를 지연 로딩하고, 단순 판단은 결정 모델·라우터로 넘기세요.** ([11/18](/ai-trends/2026/11/18/ai-trends.html), [11/19](/ai-trends/2026/11/19/ai-trends.html), [11/21](/ai-trends/2026/11/21/ai-trends.html))
