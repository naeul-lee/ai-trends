## 📌 오늘의 한 줄 요약
에이전트에게 일을 맡기는 것보다 **"결과를 검증할 장치"를 먼저 만드는 것**이 성패를 가른다는 사례가 eval, 코드 최적화, 하드웨어 포팅 세 곳에서 동시에 나왔습니다.

## 🎯 활용 Best Practice

### 에이전트 eval은 "eval부터 검사"하라 (Hugging Face, 11/23)
- 물리 실험(라만 스펙트럼 피팅) 과제로 에이전트 eval을 만드는 8단계를 공개했습니다. 핵심은 eval을 돌리기 전에 **오라클(통과해야 함), 아무것도 안 하는 에이전트(실패해야 함), 고의적 지름길(실패해야 함)** 세 가지로 채점기를 먼저 시험하는 것입니다.
- 실제로 피크 폭을 대충 추정하는 지름길이 8개 과제 모두에서 정답 비율을 맞춰 채점기가 속았습니다. 또 24회 시도 중 19회는 명령 출력을 보기도 전에 "완료"를 선언했고, 11회는 결과 파일조차 만들지 않았습니다.
- pass@3는 7/8이었지만 pass^3(3번 모두 성공)는 1/8에 그쳤습니다. 하네스만 바꿔도 정확도가 최대 29.9%p 달라진다는 감사 결과도 인용했습니다.
- **적용 팁:** 사내 eval에 "no-op 에이전트" 실행을 기본으로 넣으세요. 이게 점수를 받으면 채점기가 잘못된 것입니다. 무인 실행 업무라면 pass@k가 아니라 **pass^k**로 보고하고, 모델을 비교할 때는 추론 제공자를 고정하세요.
- 🔗 [Hugging Face Blog](https://huggingface.co/blog/agentic-evals)

### 반증 가능한 가설로만 코드를 바꾼다: Agentic Algorithm Engineering
- 하이델베르크대 알고리즘 공학 그룹이 Claude Code/Codex용 최적화 스킬 AAE를 공개했습니다. 시작할 때 벤치마크·지표·정확성 검증·예산을 합의하면, 에이전트가 **"X를 바꾸면 이유 Y 때문에 지표가 약 Z만큼 좋아진다"** 는 가설을 세우고, 측정 전에 효과를 예측하고, 최소 변경 → 정확성 검증 → 벤치마크 순으로 진행합니다. 빨라지지 않거나 틀리면 되돌립니다.
- 그래프 분할 도구 KaHIP kaffpa 세션에서는 실험 122회, 가설 69개 중 패치 41개가 채택돼 3.9배 빨라졌고 분할 품질은 그대로였습니다. 최소 컷 도구 VieCut은 8.9배 빨라졌습니다.
- **적용 팁:** 성능 작업을 맡길 때 "빠르게 해줘" 대신 ① 고정 벤치마크 ② 출력 동일성 assert ③ 변경 1건 = 커밋 1건 = 가설 1개 규칙을 주세요. 기각된 가설 기록도 남게 되어 리뷰가 쉬워집니다.
- 🔗 [AAE 프로젝트 페이지](https://chszlab.github.io/AgenticAlgorithmEngineering/)

### 사람 없이 밤새 돌아가는 테스트 루프: $9 MP3 플레이어에 Rockbox 포팅 (11/14, HN 화제)
- 문서가 전혀 없는 중국산 MP3 플레이어에 오픈소스 펌웨어 Rockbox를 LLM으로 포팅한 기록입니다. 대부분은 Claude(Opus 5.5)가 했고, Ghidra MCP로 펌웨어를 분석했습니다.
- 잘 된 것: USB 시리얼 개발 셸(키 입력·스크린샷 전송)로 에이전트가 혼자 기기를 조작하게 하고, 몇 시간씩 버튼을 무작위로 누르는 monkey 테스트 로그를 에이전트가 검토했습니다. **역공학 에이전트 → 하드웨어 사실만 남기는 심판 → 구현 에이전트**로 나눈 클린룸 구성도 썼습니다.
- 실패한 것: 앞서 시도한 다른 에이전트는 5일 동안 일회성 스크립트 443개, 문서 384개, 파일 387만 개(약 55GB)를 만들며 헤맸습니다. FM 튜너 주파수가 4MHz 어긋난 문제는 사람이 알아챌 때까지 풀리지 않았습니다.
- **적용 팁:** 하드웨어·임베디드 작업이라면 복구/다운로드 모드 절차를 처음부터 알려 주고, 스캐폴딩은 최소한으로 유지하세요. 사람의 역할은 PM과 QA(재부팅, 소리 듣기)로 좁히면 됩니다.
- 🔗 [jayd.ml](https://jayd.ml/2026/11/14/rockbox-on-yp3.html)

### 벤더가 말한 수치는 직접 재라: 지연 시간으로 모델 정체 추정 (Modaic, 11/24)
- TypeSafe가 정체를 밝히지 않은 판단 전용 모델 Jev를 분석해, Qwen3.5-35B-A3B(희소 MoE)일 가능성이 높다고 결론 냈습니다. 9,984개 프롬프트에서 **Qwen 토크나이저가 TypeSafe가 보고한 토큰 수보다 지연 시간을 더 잘 예측했습니다.**
- 저자들도 추정이 근사치라는 점과, 같은 구조의 모델(Qwen3.5 vs 3.6)은 구분할 수 없다는 한계를 밝혔습니다.
- **적용 팁:** 블랙박스 API를 도입할 때는 입력 길이별 p50/p99 지연과 처리량을 직접 측정하세요. 보고된 토큰 수가 실제 과금 기준과 맞는지도 샘플로 확인할 가치가 있습니다.
- 🔗 [Modaic Blog](https://modaic.dev/blog/latency-doesnt-lie)

### 과학자들이 에이전트에게 맡기지 않는 것 (Ai2, 11/25)
- 미국 과학자 17명을 인터뷰한 탐색적 연구입니다. 데이터 처리, 코드 작성, 실험 절차 문서화, 반복 행정 업무는 기꺼이 맡기지만, 연구 아이디어 생성과 동료의 미발표 원고 리뷰는 맡기지 않겠다는 응답이 나왔습니다. 여러 명이 AI 요약 대신 원문을 직접 대조했습니다.
- **적용 팁:** 팀에 에이전트를 도입할 때 "위임 가능 / 검토 후 사용 / 금지" 업무 목록을 구성원이 직접 정하게 하세요. 신뢰 기준(검증·프라이버시·객관성·책임·투명성)을 체크리스트로 쓸 수 있습니다.
- 🔗 [Hugging Face Blog (Ai2)](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents)

## ⚙️ LLM 서빙/인프라

### 에이전트가 반나절 만에 디코드 40% 향상: Inkling 2 Mini on RTX PRO 6000 (11/25)
- 코딩 에이전트가 `inference-optimisation` 스킬과 HF Jobs로 유효 벤치마크 46회를 돌렸습니다. 단일 사용자 디코드는 136 → 190.6 tok/s, 8명 동시 처리량은 약 570 → 716 tok/s가 됐습니다.
- 순서: SGLang → vLLM nightly 전환(+15%), DSpark 추측 디코딩(드래프트 토큰 7개, +21%), 96GB VRAM에 맞춘 `--max-model-len`·`--gpu-memory-utilization` 조정.
- **적용 팁:** 단일 GPU 셀프 호스팅이라면 엔진 교체와 추측 디코딩을 먼저 실험하세요. 이런 탐색은 측정 지표가 분명해서 에이전트에게 맡기기 좋습니다.
- 🔗 [Hugging Face Blog](https://huggingface.co/blog/inkling-2-mini-inference-hillclimb)

### LoRA rank를 데이터셋 크기로 미리 계산하기 (Engram, 11/24)
- 베이스 모델 기준으로 데이터셋이 몇 비트인지 재면 그것을 담을 최소 LoRA rank를 예측할 수 있다고 밝혔습니다. 권장 방법은 예측값의 0.5~2배 범위에서 학습해 데이터의 95%를 담는 가장 작은 rank를 고르는 것입니다. 실험은 Qwen3.5-0.8B에서만 했습니다.
- 🔗 [Engram Blog](https://engram.com/blog/lora-size)
