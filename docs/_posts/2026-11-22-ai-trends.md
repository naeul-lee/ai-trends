## 📌 오늘의 한 줄 요약
이번 주말 사례들이 공통으로 말하는 것은 **"에이전트 권한은 게이트웨이와 승인 정책으로 묶고, AI가 찾은 버그는 사람의 리뷰 시간까지 예산에 넣으라"** 입니다.

## 🎯 활용 Best Practice

### 도구 호출도 "게이트웨이 뒤"로: LangSmith Tool Gateway (LangChain, 11/19)
- 에이전트와 MCP 서버 사이에 두는 관리형 계층입니다. 에이전트는 **"툴 킷" URL 하나**만 보고, 그 킷에 든 도구만 쓸 수 있습니다. 호출마다 신원 확인 → 정책 적용 → 전달 → 기록 순서로 처리합니다.
- 신원은 두 가지로 나뉩니다. 대화형 에이전트는 **사용자 본인 계정**으로, 백그라운드 에이전트는 관리자가 한 번 연결해 둔 **공유 프로필**로 호출합니다. 거부 정책과 승인 정책(민감한 호출은 사람이 확인)을 둘 수 있고, 호출마다 트레이스가 남습니다.
- **적용 팁:** 제품을 쓰든 직접 만들든 원칙은 같습니다. ① 에이전트에게 서버 전체가 아니라 **필요한 도구 묶음만** 주세요. ② "사용자 대리"와 "에이전트 자체" 자격 증명을 나누세요. ③ 쓰기 작업에는 승인 정책을 거세요. ④ "밤사이 에이전트가 누구 권한으로 무엇을 했나"에 답할 수 있게 호출 로그를 남기세요. (11/16에 다룬 "코딩 에이전트는 게이트웨이 뒤에" 원칙을 도구 호출로 넓힌 것입니다.)
- 🔗 [LangChain 블로그](https://langchain.com/blog/langsmith-tool-gateway) · [문서](https://docs.langchain.com/langsmith/tool-gateway)

### 운영 에이전트는 "제안만, 적용은 승인 후": Genie ZeroOps 공개 베타 (Databricks, 11/19)
- 파이프라인·잡·테이블·ML 모델을 감시하고, 장애가 나면 원인을 찾아 수정안을 내는 백그라운드 에이전트입니다. 수정안은 운영 테이블의 얕은 복제본(shallow clone)을 쓰는 격리 샌드박스에서 먼저 검증합니다. Databricks는 **"테스트한 것이 그대로 적용되며, 승인 전에는 아무것도 운영에 반영되지 않는다"** 고 설명합니다.
- 보도에 따르면 비공개 프리뷰에서 실제 고객 이슈 8만 건 이상을 관찰했고, 베타에서는 Git 기반 잡의 수정안을 PR로 바로 만들 수 있습니다. (2차 보도)
- **적용 팁:** 사내 운영 에이전트를 설계할 때 같은 순서를 쓰세요. **감지 → 원인 분석 → 수정 코드 → 운영 복제본에서 검증 → PR로 사람 승인.** "검증한 변경과 적용할 변경이 같은지" 확인하는 단계가 핵심입니다.
- 🔗 [Databricks 블로그(6월 발표)](https://www.databricks.com/blog/introducing-genie-zeroops) · [Unite.AI 베타 보도](https://www.unite.ai/?p=527517)

### AI가 버그를 더 찾으면 "리뷰 병목"이 온다: PostgreSQL 19 지연 (11/19 출시)
- PostgreSQL 19가 평소보다 두 달 늦게 나왔습니다. 커미터 Robert Haas는 그 주된 원인으로 **LLM 사용자들이 신고한 버그의 급증**을 꼽았습니다. 이전 릴리스 브랜치 백패치 커밋이 248건에서 433건으로 74% 늘었고, 큰 기능 세 개가 베타 막바지에 되돌려졌습니다.
- Haas는 이 버그들이 진짜이고 사람이 찾기 어려운 것들이었다고 말합니다. 다만 LLM이 쓴 수정 패치는 늘 맞지는 않아서, 모든 변경을 사람이 리뷰하고 커밋해야 했습니다.
- **적용 팁:** ① AI 보안·버그 스캐너를 도입하면 **찾는 속도보다 고치고 리뷰하는 인력**을 먼저 계산하세요. ② 오픈소스에 AI로 찾은 버그를 신고한다면 직접 재현하고 범위를 좁힌 뒤 보내고, AI가 쓴 패치는 프로젝트 규칙에 맞는지 확인하세요.
- 🔗 [Robert Haas 블로그](https://rhaas.blogspot.com/2026/10/postgres-19-is-late-and-its-ais-fault.html) · [PostgreSQL 19 발표](https://www.postgresql.org/about/news/postgresql-19-released-3449/) · [Simon Willison](https://simonwillison.net/2026/Nov/19/postgresql-19/)

## 🤖 새로운 모델

### 추론 레벨 한 단계에 비용 6배: Gemini 4 Hydrogen `xhigh` (11/20)
- Simon Willison이 llm-gemini 0.38.1에 Gemini 4 Hydrogen·Neon의 `xhigh` 추론 레벨을 추가하고 같은 프롬프트로 비교했습니다. `high`는 출력 5,311토큰·3.99센트·19초, `xhigh`는 31,477토큰·23.61센트·2분 36초였습니다. 결과물은 더 좋아졌다고 합니다.
- **적용 팁:** 추론 레벨은 모델 교체만큼 비용을 바꿉니다. 기본값은 낮게 두고, 품질 차이가 eval에서 확인되는 작업에만 높은 레벨을 쓰세요.
- 🔗 [Simon Willison](https://simonwillison.net/2026/Nov/20/llm-gemini/)
