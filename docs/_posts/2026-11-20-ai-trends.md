## 🎯 활용 Best Practice

### 문제 22개, 에이전트 22개, 그리고 중복 검증 (Anthropic, 11/17)
- 연구자가 Claude에게 블랙홀 물리 분야의 미해결 문제 목록을 받아(22개) **문제마다 에이전트를 1개씩** 배정했습니다. 에이전트끼리 진행 글을 읽고 협업할 수 있게 해 6주간 백그라운드로 돌렸습니다.
- 결과: 2003년부터 끝나지 않았던 Hawking-Page 전이 계산을 완료하고, modular bootstrap에서 가장 가벼운 블랙홀 질량 상한 M₁ ≤ c/Λ (Λ ≈ 9.1266)를 찾았습니다.
- 신뢰의 근거는 구조에 있습니다. 계산 대부분을 **서로 독립된 에이전트가 두 번** 수행했고, 기존 논문 값과 대조했으며, bootstrap 결과는 **Lean으로 형식 검증**했습니다. 마지막으로 물리학자가 주요 결과를 모두 확인했습니다.
- 다른 문제(sphere-packing)를 풀던 에이전트의 기법이 61번 실패한 문제를 풀었습니다. 공유 게시판이 효과를 낸 사례입니다.
- **적용 팁:** 장기 에이전트 작업은 ① 문제를 작게 쪼개 1:1로 배정하고 ② 핵심 결과는 독립 실행 2회로 교차 확인하며 ③ 알려진 정답을 재현하는지 먼저 점검하고 ④ 가능하면 기계 검증(테스트·증명)을 붙이세요.
- 🔗 [Anthropic Research](https://www.anthropic.com/research/claude-black-hole-physics)

### 한 모델은 가설, 다른 모델은 반증: 잃어버린 코드 복원기
- Apache DataSketches의 Rust 포트에는 원저자(작고)의 OCaml 생성기 없이 정적 테이블만 남아 있었습니다. 개발자는 모델 3개에 역할을 나눠 생성 로직을 역설계했습니다.
- 역할 분담: Gemini 4 Carbon은 후보 생성기와 하네스를 작성, Claude Opus 5.5는 ablation으로 초기 가설을 **반증**, GPT 6 Astra는 **mutation testing**으로 감사했습니다.
- 교훈: 그럴듯한 설명도 코드로 흔들면 무너집니다. 실제로 상수를 망가뜨려도 통과하는 **자기참조(tautological) 테스트 2개**가 mutation testing으로 드러났습니다.
- **적용 팁:** AI가 쓴 테스트는 그대로 믿지 마세요. 코드를 일부러 망가뜨렸을 때 실패하는지(mutation test) 한 번 돌려 보세요. 검토 모델은 작성 모델과 다른 것을 쓰세요.
- 🔗 [tisonkun.io](https://www.tisonkun.io/posts/ai-repair-program/)

### "에이전트 팀" 제품 3종 동시 출시: 고르기 전에 볼 것 (11/17)
- **Replit Missions:** 목표·예산 상한·승인이 필요한 행동을 먼저 정하면 swarm이 병렬로 만들고, AI judge가 합격 기준으로 판정합니다. Replit 자체 수치로는 모니터링 도구 DataCat을 2일·$3,000에 만들었고, NumPy 최적화 과제에서 에이전트 1개는 최대 4배, 16개는 17배, 32개는 19배 속도 향상을 보였습니다. (독립 검증 없음)
- **Cognition Devin Bots:** 상주형 "매니저" 에이전트가 프로젝트를 쪼개 여러 Devin 세션에 넘깁니다. Fortune 보도에 따르면 Bots는 별도 클라우드 머신에서 돌아 엔지니어 노트북의 키·비밀번호와 분리됩니다.
- **Perplexity Computer Multiagent:** 리드 에이전트 아래 최대 16개 에이전트가 증거를 공유하고 서로 교차 검증합니다. (2차 보도 기준)
- **적용 팁:** 16개에서 32개로 늘려도 속도는 17배에서 19배로 수익이 급감했습니다. 에이전트 수보다 **측정 가능한 합격 기준**과 **예산 상한**, **외부 행동(배포·발송·외부 API) 승인 게이트**를 먼저 설계하세요.
