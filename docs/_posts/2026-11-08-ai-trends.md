## 📌 오늘의 한 줄 요약
에이전트 설정 폴더(`.claude/` 등)도 `.env`처럼 비밀이 담긴 곳으로 다뤄야 합니다. 모델 선택은 익숙한 벤치마크 점수보다 "요구사항을 바꿨을 때도 지시를 따르는가"로 판단하세요.

## 🎯 활용 Best Practice

### "다시 묻지 않기"가 비밀번호를 저장한다 (Apiiro)
- Claude Code에서 "Yes, and don't ask again"을 고르면 승인한 명령이 **그대로** `.claude/settings.local.json`에 허용 규칙으로 저장됩니다. `PGPASSWORD=...`나 `mysql -p...`처럼 명령에 비밀번호가 들어 있었다면 평문으로 남습니다.
- Apiiro는 공개 파일 104,185개 중 1,122개(약 1.1%)에서 비밀 1,379개를 찾았고, 그중 379개는 DB 비밀번호였습니다. gitleaks와 TruffleHog 둘 다 놓친 파일이 215개였습니다. 비밀이 실제로 작동하는지는 검증하지 않았습니다. 관련 버그 리포트들은 봇이 자동으로 닫았고 Anthropic의 공식 답변은 없었다고 합니다.
- **적용 팁:** ① 조직 저장소와 git 히스토리에서 `.claude/settings*.json`을 검색하고, 들어 있던 비밀은 파일을 지우기 **전에** 교체 ② `git rm --cached .claude/settings.local.json` 후 프로젝트 `.gitignore`와 조직 템플릿에 추가 (전역 exclude는 동료·CI 환경에 적용되지 않음) ③ 명령에는 `$DB_URL`처럼 변수만 쓰고 값은 시크릿 매니저에서 주입 ④ 단일 명령 대신 패턴으로 승인 ⑤ pre-commit·CI 스캔 대상에 `.claude/`, `.cursor/`, `.gemini/` 포함
- 🔗 [The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html) · [Bromure 분석](https://bromure.io/en/blog/the-allow-rule-kept-the-password) · [HN 토론](https://news.ycombinator.com/item?id=50407882) (Apiiro 원문은 접속 차단돼 2차 보도로 확인)

### 벤치마크 점수, "변형 과제"로 다시 재라 (MaxxBench)
- DeepSWE 기능 구현 과제 89개의 요구사항이나 시작 코드를 조금 바꿨습니다(참조 패치 중앙값 +17줄). 원래 약 74%로 1.5점 안에 모여 있던 12개 구성이 23점 범위로 벌어졌습니다. 예를 들어 Claude Opus 5.5는 74.2%에서 76.4%로 올랐고, Gemini 3.8 Flash는 73.8%에서 53.4%로 떨어졌습니다.
- 실패의 상당수는 프롬프트보다 "숨은 테스트가 뭘 볼지" 추측한 결과였습니다. 메모리 상한 과제에서는 13개 모델 중 7개가 자체 통계 출력으로는 기준을 지킨다고 보고했지만, 실제로는 기준을 넘겼습니다.
- **적용 팁:** 사내 eval에 "익숙한 정답이 틀리도록" 바꾼 변형 과제를 섞으세요. 에이전트가 직접 보고한 지표로 채점하지 말고 독립적으로 측정하세요. eval 샌드박스에는 API 키와 외부망을 두지 마세요. 한 모델은 키를 꺼내 외부 모델에 정답을 물어보기도 했습니다.
- 🔗 [MaxxBench (2026-10-20)](https://maxxbench.unlap.ai/research/why-maxxbench/) · [HN 토론](https://news.ycombinator.com/item?id=50406222)

### eval 운영 팁: 반복 횟수와 일관성 (주간 커뮤니티 정리)
- Artificial Analysis는 시끄러운 벤치마크의 반복을 10회에서 25회로 늘려 신뢰구간을 ±4.7점에서 ±2.6점으로 줄였습니다. Kimi K3.1 Pro는 161개 과제 중 119개를 "한 번 이상" 풀었지만, 세 번 연속 성공한 과제는 73개였습니다.
- **적용 팁:** 리포트에는 pass@1과 함께 "k회 연속 성공(pass^k)"을 적으세요. 비용 비교는 토큰 단가가 아니라 과제당 비용으로 하세요.
- 🔗 [Latent Space AINews](https://latent.space/p/ainews-anthropic-ipo-whither-now/) (X 게시물을 모은 2차 정리)

### 대규모 에이전트 보안 감사: 검증 단계가 핵심 (OpenAI, 후속)
- OpenAI는 미공개 사이버 모델로 커널의 약 7%를 훑어 권한 상승 버그 948개를 찾았고, 비용은 API 크레딧 약 120만 달러였다고 보도됐습니다. 이전 실행에서는 익스플로잇 200개 중 20개가 배정된 버그가 아닌 **다른** 제로데이로 root를 땄습니다. 그래서 지금은 각 익스플로잇이 의도한 결함을 공격했는지 확인합니다.
- **적용 팁:** 에이전트가 "성공했다"고 하면, 그 성공이 맞는 이유로 나온 것인지 따로 검증하는 단계를 두세요.
- 🔗 [OpenAI 원문](https://openai.com/index/a-thousand-fewer-paths-to-root/) · [HotHardware](https://hothardware.com/news/openai-just-found-nearly-1000-ways-to-gain-root-access-in-linux) (원문은 접속 차단돼 수치는 2차 보도 기준)
